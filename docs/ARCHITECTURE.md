# 架构说明

## 设计目标

V2 将 V1 的单体流程拆成职责清晰、可以独立测试的模块。核心目标是可维护、可审计，并让外部系统写入始终受权限策略控制。

| 模块 | 职责 | 设计价值 |
|---|---|---|
| `contracts` | 定义输入任务与统一结果 | 减少模块间隐式约定 |
| `scoring` | 计算机会分与优先级 | 规则可替换、可测试 |
| `safety` | 判断操作是否允许 | 高风险动作默认拒绝 |
| `orchestration` | 编排完整处理流程 | 业务顺序集中可读 |
| `execution` | 隔离外部系统调用 | 展示环境仅模拟执行 |
| `results` | 统一输出状态 | 便于日志和上层消费 |

## 请求生命周期

1. 输入转换为不可变的 `CompanyTask`。
2. 评分器根据公开示例信号计算分数。
3. 路由器决定“跟进”或“观察”。
4. 权限闸门验证执行模式和审批状态。
5. 模拟执行网关返回标准化结果。

这一拆分让评分逻辑、权限策略和外部连接器可以分别演进。
